# Infusion De-ID — page architecture (v0.11)

One HTML file, no server, no install, no network. Everything below runs inside the browser tab.

## 1. How the file is assembled

`build.js` reads `src/index.html` and replaces each `<!--INLINE:…-->` marker with the file's contents inside a `<script>` tag, in this order:

| Order | File | Role |
| --- | --- | --- |
| 1 | `vendor/xlsx.full.min.js` | SheetJS 0.20.3 (patched for CVE-2023-30533 and CVE-2024-22363): reads and writes .xlsx/.xls/.csv |
| 2 | `src/dict.js` | 275k English words as a Bloom filter (about 0.5% false positives), generated by `tools/build-dict.js` |
| 2b | `src/biglex.js` | 190k-name lexicon (Census surnames, SSA first names, English word list), generated by `tools/build-lexicon.js` |
| 3 | `src/lexicon.js` | Curated lists and the name-tier functions built on biglex |
| 4 | `src/core.js` | The whole de-identification pipeline. No DOM: the same file runs in Node for tests |
| 5 | `src/synth.js`, `src/evaluate.js` | Synthetic test data and scorer for the "Check accuracy" tab |
| 6 | `src/ocr.js` | Wrapper that runs Tesseract inside a Web Worker |
| 7 | OCR assets (OCR build only) | Tesseract engine, worker script and English model, embedded as inert `<script type="text/plain">` blocks |
| 8 | `src/app.js` | The page: input, session, review, verdict, export |

Two outputs: `dist/infusion-deid.html` (3.6 MB, no OCR) and `dist/infusion-deid-ocr.html` (11.3 MB, with OCR).

A Content-Security-Policy meta tag (`default-src 'none'; connect-src 'none'`) blocks network requests in browsers that enforce CSP. Only inline scripts, `blob:` workers and `data:`/`blob:` images are allowed. The page badge says "Runs locally · network blocked": that is what the browser enforces, and it says nothing about files a user saves.

## 2. Layers

```
 ┌──────────────────────────── app.js (page) ─────────────────────────────┐
 │ Drop zone / paste / Patient list → items → session → verdict → export │
 └───────┬──────────────────┬───────────────────┬─────────────────────────┘
         │                  │                   │
   SheetJS (read)     ocr.js → Tesseract     core.js  ←── lexicon.js ← biglex.js
                      (Web Worker, wasm)        │
                                                ▼
                         classify → census → detect → resolve → surrogate → self-check
```

## 3. The page (`app.js`)

**Inputs.** One drop zone routes by content: .xlsx/.xls/.csv go to the table path, text or Ctrl+V text to the text path, images to OCR, a saved session key to restore. File size and table size are checked first (`checkFileSize`, `tableLimits`).

**Items.** Every input becomes an item: a table, pasted text or a screenshot. Each item keeps its source table, column roles, result, manual review edits and status. Items are processed one at a time through a queue (`enqueue`), so a slow file can't race a fast one.

**Session.** One `registry` per page session holds every real patient seen so far: code (P001…), made-up name, date offset, all known spellings, MRNs and birthdates. Every item is processed against it, so the same person gets the same code across files and screenshots. It can be seeded three ways: from earlier items, from the **Patient list** (a pasted schedule or roster that produces no output, `seedRoster`), or from a saved session key (`restoreSession`). When a later input teaches the registry a name, earlier items re-run (`healEarlier`, `rerunAll`).

**Processing.** `processItem` calls `DeID.processTable`. Large tables (over about 1,200 rows) go through `processInParts`, which yields to the browser between chunks so the tab stays responsive and shows progress. The parts are then merged (`mergeParts`).

**Self-check.** `selfCheckOf` scans the protected output for any identifier the registry knows, in any spacing or case. It also flags patients whose name couldn't be read, and any processing error.

**Verdict and gating.** `blockReason` and `setDownloadState` decide what can be downloaded:
- **Release check passed**: the self-check had patients to check against and found nothing, and the release scan found nothing.
- **Review required** (`needsReview`): a text or screenshot item with no patient list, or source words that survived and are not ordinary words (`releaseScan().words`). Downloads need *I have reviewed this*, stored as `item.ackKey` and valid only while it equals `item.resultKey`.
- **Blocked**: an error, a self-check hit, a release-scan identifier, an unread name, or a table with no patient column. Every download for that item and Download all are disabled (`failItem`, `renderError`).

**Result key.** `resultKey` binds a result to the tool version, the registry stamp, the item's column roles, options, word lists and manual edits. `blockReason` refuses any result whose key no longer matches, so a stale result can never be exported.

**Registry transactions.** `processItem` takes `registry.checkpoint()` before a run and calls the returned rollback if the run fails, so a failure leaves no half-learned patient.

**Release step.** `releaseExport` is the only path to a protected download (xlsx, CSV, text, report, Download all, per-source). It re-asks `blockReason` for every item, builds the bytes, re-reads them (`XLSX.read` for workbooks, an RFC 4180 reader for CSV), and verifies sheet names, cell values, the absence of formula cells and formula-like strings, and that no identifier-column value (`findNeedles`) appears. Any failure saves nothing.

**Review.** The review table highlights every replacement with its source (patient list, rule, word clue). You can untick a highlight or mark missed text, which re-runs the item with your edits.

**Export.** Protected .xlsx, .csv, .txt, a run report and Download all. Every cell passes through `safeCell` to neutralise spreadsheet formulas. Output filenames never contain the source name. The session key (real names, MRNs, offsets) is a separate red button and never downloads on its own.

**Other tabs.** Check accuracy (synthetic set, adversarial cases, ablation), Restore identities (protected file plus key back to real), About.

## 4. The pipeline (`core.js`, `processTable`)

`processTable` wraps `processTableCore` so it never throws. On error it returns a blanked result with `errors` filled in (`failedResult`), and the page treats that as red.

1. **Normalise** (`normalizeText`): NFC, strip zero-width characters and BOM, turn non-breaking spaces into plain spaces, straighten curly quotes.
2. **Classify columns** (`classifyColumns`): each column becomes patient name, MRN, DOB, account, phone, provider, date, age, ZIP, free text, keep, or drop. The decision comes from header patterns and the values, and the user can override it. Pasted text and OCR go through `parseTextDocument` instead, which builds a per-line patient census: "Last, First", MRN and DOB per line, carried forward to following lines, with names wrapped across lines rebuilt and tile layouts paired.
3. **Census** (`buildCensus`): every row's patient is resolved in the registry (`createRegistry().resolve`, matching on MRN, then name plus birthdate, then a cautious fuzzy name that needs a birthdate). Every spelling of every known patient becomes a lookup entry: full name, "Last, First", initials, nickname, run-together and hyphen-split forms, MRN with and without zeros, birthdate renderings, phone and account. Patients from the Patient list and earlier inputs join as `known`.
4. **Detect** (`detectText` → `detectTextCore`), per text cell, cut into chunks above 6,000 characters:
   - `censusSpans`: exact matches against the census. This is the most reliable layer.
   - `ruleSpans`: fixed-format identifiers. Phones (including written-out and extensions), emails, URLs, SSNs and last-4, MRN and record-number patterns learned from the MRN column, insurance member IDs, addresses, ZIPs, ages 90+, and dates in about a dozen formats, with guards so doses, scores and cycle fractions stay.
   - `lexiconSpans`: about 40 passes for names, organisations and places. They use name tiers (strong names stand alone, rare names need company, word-names need a cue), honorifics, credentials, relation words, contact verbs, "Pt"/"for"/"with" cues, greetings, nicknames, lower-case names, facility words and place cues.
   - `strictSpans` (on by default): any capitalised word, or a lower-case word that is a known name, that is not in the 275k-word dictionary (`src/dict.js`, a Bloom filter), the clinical allowlist, a drug stem or medical ending, or a dose/regimen context is removed as a name or place. Also labelled places ("City  Springfield"), rows of ALL-CAPS "LAST, FIRST" names, and ages 90+ said in words ("is 97 now").
   - Clean-up: `resolveSpans` settles overlaps by priority, `mergeAdjacentNames` and `finishNames` complete half-caught names, `collectPropagation` re-finds detected names across the document, and the clinical allowlist protects eponyms and drugs.
5. **Surrogate** (`Surrogator`, `applySpans`): patients get their registry code or made-up name, consistent everywhere. Relatives and providers get consistent fakes. Dates shift by the patient's offset with the original format kept. Ages 90+ are grouped, ZIPs truncated to 3 digits, phones become 555-01xx, and organisations and towns are replaced with invented ones. Surrogates are chosen so they never equal a real word from the document. The audit column records counts, never the offset.
6. **Self-check** (`selfCheck`): one combined pattern per cell, built from the registry, scans the output. Any hit, unread name or error blocks the item.
7. **Release scan** (`releaseScan`), independent of the detectors: compares output with source. Identifier-column values (patient last names that are not ordinary words, MRN/account/phone digits in any separator form) found anywhere in the output block the item; capitalised source words of 4+ letters that survived unchanged and are not dictionary, clinical, drug-stem or allowlisted words (eponym contexts excepted) form the review queue.

Surrogate details for Safe Harbor: ZIPs keep 3 digits except the 17 restricted prefixes (036, 059, 063, 102, 203, 556, 692, 790, 821, 823, 830, 831, 878, 879, 884, 890, 893), which become `000`; a birth year is never kept for ages 90+.

## 5. OCR path (`ocr.js`)

A Blob-URL Web Worker gets the Tesseract wasm glue, the worker script, and a `fetch` shim that serves the embedded English model from memory, so nothing is fetched. Images are upscaled, converted to grayscale, and inverted if the theme is dark. Recognised text is shown in an editable box ("Use my corrections"), passed through `normalizeOcrText` to fix common misreads, then sent down the text path. The screenshot image itself is never modified or exported.

## 6. Data that persists

- **In the browser:** only column-role layouts per header signature, in localStorage. No patient data.
- **Downloads only:** the protected files and, separately and only on request, the session key.

## 7. Tests (not part of the page)

| Command | What it proves |
| --- | --- |
| `node --test test/unit.test.js` | 118 behaviour tests across detection, surrogation, registry, dates, robustness |
| `node test/run_eval.js` | Synthetic set: recall per category, over-redaction (0.0%), ablation, adversarial cases |
| `node test/e2e.js` | Playwright drives the built file: upload, review, every download, Patient list, fail-closed gating, OCR linking across screenshots, no network requests |
| `node test/robust.js` | 23 property, fuzz and timing checks: never throws, no regex hangs, census names never survive, workbook side channels (comments, hyperlinks, hidden columns, other sheets) never reach output, formula injection blocked |
| `node test/redteam/score.js --ocr` | Fixed scorer over 11 rounds of blind red-team cases, screenshots through the real OCR page |
